# Development

## Runtime and architecture

The [architecture review](docs/ARCHITECTURE_REVIEW.md) records current responsibility/dependency hotspots and proposed refactoring stages; [AST and contract measurements](docs/architecture-metrics.json) provide the supporting snapshot. Those stages are recommendations, not implemented module boundaries.

Use Python 3.12 (`backend/.python-version`), Node 24 (`frontend/.nvmrc`), uv and npm. Dependencies are locked in `backend/uv.lock` and `frontend/package-lock.json`. Run `python arcade.py --setup` once, then `python arcade.py --dev`. No CI/CD services or workflows are configured.

React owns the console and menus. `GameCanvas` renders session presentation; `useGameSession` manages asynchronous lifecycle effects, clocks, and persistence; `services/lifecycle.ts` validates phase transitions. The SDK engine owns a fixed 60 Hz simulation, bounded catch-up, a 60 FPS render cap, frame sampling, and input consumption. Pause cancels frame callbacks until resume. Game state stays outside React.

Route pages load lazily; Settings imports backup tooling when an action needs it. The root error boundary wraps `App` and offers backup export before retry/reload. `watchVisibleTask` cancels pending timers and aborts cancellable work while hidden. Connection status is shared through `useLocalConnection`; local loopback checks remain available when the browser reports no Internet connection. Queue retry scheduling stops when empty/blocked, follows each result's backoff and uses Web Locks across tabs when supported. Server receipts preserve idempotency on the fallback path. Controller menu polling sleeps without a connected device and while hidden; native connection events resume it, with held-button suppression after visibility returns.

`catalog.json` owns bundled modes, rules versions, score units, difficulty support, and tuning defaults. The Python seed consumes it; frontend descriptors validate it and attach lazy loaders and controls metadata. Game state/configuration validation remains game-specific. There is no legacy synchronous registry. Catalog marketing copy and achievement definitions live in the backend seed; controls and tips live in `games/experience.ts`.

FastAPI serves the API and optionally the built frontend at one loopback origin. SQLite uses foreign keys, WAL and migrations. `0004_progress` adds mode records, recovery, and stored completion receipts. Startup creates a backup before upgrading an existing database. Do not edit previously applied migrations.

## Contracts

- All player requests carry `X-Profile-ID`; activation is per browser tab. Profiles are local selectors, not authentication.
- Profile mutations invalidate older list responses. Requests share a list read only within the same revision; a late activation cannot undo a newer selection. Successful creates/deletes update the local list before refreshing, so a failed follow-up read does not hide a created player or resurrect a removed one.
- `POST /api/stats/{slug}/start` reserves a session UUID. A temporary server outage permits local play; completion can create a missing session.
- `POST /api/progress/{slug}/complete` commits immutable result, playtime, mode record and qualified awards in one transaction. The stored receipt is replayed exactly for an identical UUID/payload. Conflicting payloads return 409. Existing legacy completed sessions can be upgraded without double-counting duration.
- The engine adds `metrics.ended` when simulation returns a terminal result, independently of objective completion or a recoverable collision. New terminal receipts delete only matching recovery in the same transaction; late checkpoints for an ended UUID return 409. Ordinary quits and technical errors carry `ended=false` and retain resumable state. Legacy results without the flag keep the prior completed/crashed fallback. Undo clears the engine's terminal flag before continuing. A standalone legacy `/session` now counts its new run once; finishing a reserved start never increments it again.
- The browser completion queue persists before sending, retries temporary failures with bounded backoff, and retains permanent 4xx failures for explicit retry/export in Settings. Durable entries reconcile with storage so another tab's successful submission removes stale pending results. Failed storage writes retain a separate in-memory fallback. Existing v1 queue entries remain readable.
- `GET /api/progress/records?household=true` includes other active local players. Compare like modes/difficulties/rules; an aggregate legacy high score remains available through stats for compatibility.
- `GET /api/progress/history?skip=0&limit=25&game_id=...` returns a real total and a page of completed sessions. `mode`, `difficulty`, timezone-aware `since`/exclusive `before`, `sort` and `direction` apply before pagination. Allowlisted sorting uses an ID tie-breaker; rows and totals share one predicate. Legacy null difficulty matches normal. `/api/progress/history/options` returns the current player's historical games/modes, including retired catalog entries. The UI converts local calendar dates to inclusive/exclusive ISO bounds before requesting results.
- `GET /api/progress/recovery`, `PUT/DELETE /api/progress/recovery/{slug}` manage one recovery save per player/game, independently of manual slots.
- Recovery writes serialize per player/game and coalesce consecutive waiting snapshots to the newest board. Deletes preserve ordering and session guards; clearing a pending snapshot can replace its unsent write. A slow request in one player's queue does not block another player's saves. Browser/memory recovery updates immediately even when server writes fail.
- `GET /api/achievements/summary` returns only the current player's active-catalog totals in one aggregate query. Achievement pages use one aggregate plus one joined page query, without loading all unlock rows or related game objects. Profile overview requests these counts and fetches history only when its dialog opens. Progress labels pending reads, aborts abandoned requests and ignores older view revisions, including rapid personal/household/personal switches.
- Save envelope format 2 carries game, mode, rules version, difficulty, config, RNG-containing game state, score, timestamp and originating session UUID. Format 1 defaults to classic/rules 1. Each game validates its state and defaults newly introduced fields for old full saves; incomplete/future saves fail visibly.
- Continue/load restores a board as a **new session**. It does not reopen an immutable completed UUID. Recovery captures state, not a promise to recover every millisecond of pre-crash playtime.
- `GET /api/data/export`, `POST /api/data/import` provide validated database JSON. Export reads a consistent snapshot in nine SELECT queries, independent of player/game counts, and includes retired games with active-player data. The browser wrapper adds origin-specific preferences, recovery, and queued results, including current in-memory fallbacks. Import is transactional for database data; profile/session IDs are remapped together across database and browser entries, names are disambiguated, and originals stay intact. Invalid or unsaved browser entries after import are reported separately. Full backup export requires the local server; memory-only data lasts until the tab closes unless exported or successfully saved.
- Database backups also carry optional unfinished `reservations`, separate from completed history, so restoring a queued completion does not count an already reserved start twice. One shared mapping covers those starts, completed rows, recognized manual/recovery envelopes and browser entries, including orphan snapshot UUIDs. Old backups default to no reservations; omitted historical starts cannot be reconstructed. Stored snapshot wrappers must have the supported format; malformed types/versions return 422. Clock rollback ignores future snapshots for due-time checks and never prunes the copy just written.
- `POST /api/data/preview` applies the same semantic/schema validation as import without creating players. Settings previews the counts, player names, preference changes and invalid browser entries before confirmation, then reuses the parsed file. Import validates again at commit. `/api/data/backups` lists/creates rotated server snapshots; named download/preview/restore routes accept only generated snapshot filenames, exclude symlinks and preserve current players. Automatic JSON snapshots default to seven retained copies and a 24-hour interval, checked at startup and hourly while running. Writes use a temporary file, fsync and atomic replacement before pruning only owned snapshots. Empty households are skipped, failures are visible, shutdown cancels the scheduler, and browser-private state requires a full browser export.
- Shared key bindings are validated against other custom bindings, default aliases and reserved secondary shortcuts. Stored conflicts fall back to safe defaults; valid swaps survive hydration. Menu controls and gameplay use the same default binding table.
- Preference storage failures retain live settings, display a persistence notice and export current values over stale stored preferences. Menu and modal focus share hidden/inert/disabled/closed-disclosure rules; controller ownership changes pause play and suppress held menu buttons. System audio handles unavailable devices/nodes, suspends after the last overlapping cue, and resumes on demand; mute/zero volume does not allocate a context. Reduced-motion CSS finishes animations instead of accelerating infinite loops.

Use `/docs` or `/openapi.json` on the running server for the authoritative endpoint/schema reference. Compatibility stats/award endpoints remain available; new gameplay uses the single completion endpoint.

## Configuration

Backend settings are environment variables or `backend/.env` (see `app/config.py`). `DATA_DIR` selects persistent data; `DATABASE_URL` accepts SQLite only. `HOST` defaults to `127.0.0.1`, `PORT` to 8000. `FRONTEND_DIR` enables static production serving. `ALLOWED_HOSTS` and `CORS_ORIGINS` accept explicit JSON lists. `ALLOW_GAME_CREATION` defaults false. Normal request bodies are limited to 1 MB; data import accepts up to 20 MB. There is no `SECRET_KEY` requirement.

Vite proxies `/api` and `/health` to the local backend; `ARCADE_BACKEND_URL` overrides that development target. The normal launcher uses a fixed origin and serves production assets without Vite.

## Local checks

`python scripts/check.py` runs Ruff, pytest, ESLint, Vitest, TypeScript and Vite production build. Add `--browser` for Playwright. Browser tests launch isolated servers and a temporary database; never point them at a real household database. Install Chromium with `npx playwright install chromium` from frontend. `CHROMIUM_PATH` optionally chooses a local binary; `/usr/bin/chromium` is supported when present.

High-value regression checks cover idempotent receipts, legacy completion upgrade, profile isolation, transactional backup restore, bounded backup queries, storage failures, cross-tab retries, modal focus, pagination, saved RNG trajectories, terminal undo, actual board moves, catch-up input consumption, and browser save/retry/controller journeys. Run relevant checks during editing and the full local script before sharing a change. See [RELIABILITY.md](docs/RELIABILITY.md) for the storage and accessibility review.

Settings exposes up to ten validated browser-stored samples of recent game initialization, average FPS, frame-interval p50/p95, render size and graphics profile; export JSON when comparing devices. Invalid stored entries are ignored. See [PERFORMANCE.md](docs/PERFORMANCE.md) for the Full HD graphics policy, repeatable eight-game benchmark and remaining hardware acceptance. Headless software-rendered browser results are functional evidence, not native GPU, input-latency, memory-leak, or game-balance certification. Use [PLAYTEST.md](docs/PLAYTEST.md) for those checks.

## Scope

Keep the eight bundled games coherent: every new title must use the catalog, lazy loader, control guide, validated save state, local results, and profile records. Native installers, network multiplayer, account authentication and third-party game plugins are outside this iteration. Full nonvisual access to real-time canvas games needs dedicated design; preserve semantic menus, focus trapping, reduced motion, and keyboard navigation when changing the shell.

Stellar Flight rules 5 is an endless space journey. Its rendering-independent `SpaceJourney` stores the universe seed, route RNG, five-ring race, visited sectors, XP, ship, boost/shield state, smooth steering velocities, race times/medals, objective baselines, camera, surveys, and collision/close-pass progress. The renderer streams 27 neighboring sectors and keeps the ship at its origin for precision on long trips. `ships.ts` builds three original hulls alongside the bundled `Jet.glb`; V / controller X switches unlocked ships (Vanguard at level 3, Star Manta at level 5). Rendering is decoupled from fixed simulation steps and preserves a Full HD buffer fitted to the viewport aspect ratio. Antialiasing and full scene detail remain enabled on hardware and software renderers; slow frames never lower quality. Instanced asteroid batches and cached sector/race transforms reduce rendering overhead without changing physical obstacles. Asteroid uploads occur only when visible instance slots change, and streamed world/route neighborhoods reuse overlapping sector descriptions within a bounded 27-sector cache. The engine bed honors mute/volume, avoids duplicate automation targets, and suspends silent audio processing after fading on pause/mute/zero volume; teardown cancels pending transitions. Manual and recovery saves retain upgrades. Rules 1/2 classic/course envelopes and full v1 states migrate into endless journeys. Earlier endless saves default the new fields and advance to rules 5; historical records keep their original rules version.

Neon Tetris and Prism Rush use rules version 2; Asteroids uses rules version 1. Their random generator states are saved alongside gameplay state, so Continue retains the piece sequence, asteroid waves, and highway gates. Prism Rush keeps its simulation in `PrismRun.ts`, separate from WebGL; its renderer pools gate meshes and disposes shared GPU resources on exit. Tetris uses a seven-piece bag with simple wall/floor kicks (not a full guideline rotation system). Sprint finishes at 40 lines; completed sprints rank by elapsed simulation time under rules 2. Marathon and historical sprint records retain points.

## Gameplay iteration contracts

- `catalog.json` is the source for mode ranking. `ranking: "time"` with `rankingSince: 2` applies to Tetris sprint rules 2+. Other modes and historical rules retain points. Completed sessions carry bounded `elapsed_ms`; minimum eligible elapsed time is derived from durable sessions, including backup copies. Incomplete runs do not qualify. No additional database migration is needed.
- Shared completion receipts carry previous points/time bests and new-time-record flags. Replays normalize historical payload defaults so older queued receipts remain idempotent.
- Snake maze connectivity, 2048 puzzle solvability and undo RNG, Raptor phrase feasibility, Breakout timed power-up persistence, Flight contract baselines, and Prism rhythm continuity have deterministic tests in `improvements.test.ts`.
- Daily 2048 boards spawn no new tiles and stop on target or move limit. The DOM board reader exposes the same live board and queues commands through the game update loop.
- See `docs/GAME_IMPROVEMENTS.md` for per-game rules versions and `docs/PLAYTEST.md` for remaining human/hardware validation.
